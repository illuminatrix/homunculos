TODO: Diet libc + sbase Porting

The target userspace is:
  - dietlibc (https://github.com/ensc/dietlibc) -- minimal libc, uses
    Linux i386 syscall conventions directly.
  - sbase (https://github.com/michaelforney/sbase) -- suckless POSIX
    unix tools (cat, ls, cp, mv, echo, grep, sed, etc.)

Build (on Linux host, not in-kernel):
  - Cross-compile dietlibc: make CC="i686-elf-gcc -m32" ARCH=i386
  - Cross-compile sbase: CC="i686-elf-gcc" AR="i686-elf-ar" make
  - Both are static; our ELF loader handles the result.

Our syscall numbers already match Linux i386 for the ones we have.
Key differences from the old Toybox/musl plan:
  - dietlibc uses `socketcall` (102) for networking, not individual
    socket syscalls.
  - dietlibc uses old `signal` (48) and `sigaction` (67) syscalls
    alongside the rt_ variants.
  - sbase is simpler than Toybox -- no xattrs, capabilities, or
    complicated /proc requirements.
  - dietlibc has its own start.S and crt; needs environ/auxv setup.

===== P5: Networking (dietlibc socketcall) =====

[ ] socketcall -- SYS_socketcall (102).  dietlibc on i386 uses the
    socketcall multiplexer, NOT individual socket syscalls.
    Subs: socket, bind, connect, listen, accept4, sendto, recvfrom,
    sendmsg, recvmsg, shutdown, setsockopt, getsockopt, getsockname,
    getpeername, socketpair.
    Implement as a single dispatch function in the kernel.
